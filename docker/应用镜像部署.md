# WitPath 应用镜像部署（后端 / 前端 / AI 服务）

> 前提：目标服务器（VM-0-2-ubuntu）已运行全部中间件容器（mysql / redis /
> rabbitmq / postgresql / milvus），并已全部接入 `witpath` 网络。
> 账号、端口与 `application-dev.yaml`、`Agent/.env` 完全一致，**业务配置不做任何修改**。
>
> 唯一变化：容器之间不能用 `127.0.0.1` 互访（容器内 127.0.0.1 指容器自身），
> 改用中间件容器名（mysql / redis / rabbitmq / postgresql / milvus）。

## 0. 确认网络（已完成的操作）

中间件容器均已 `docker network connect witpath <容器名>` 接入：

```bash
docker network inspect witpath --format '{{range .Containers}}{{.Name}} {{end}}'
# 预期输出包含：mysql redis rabbitmq postgresql milvus etcd minio
```

## 1. 构建三个镜像（在项目根目录）

```bash
docker build -t witpath-backend:latest  backend/WitPath
docker build -t witpath-agent:latest    Agent
docker build -t witpath-frontend:latest frontend/WitPath
```

说明：
- 后端首次构建会在容器内全量下载 Maven 依赖（较慢），之后命中缓存层会很快；
- 前端在容器内执行 `npm ci + npm run build`（含类型检查）；
- **`application-secret.yaml`（OSS 凭证）会随 jar 打进后端镜像，只能推私有仓库，禁止公开分发**。

## 2. 启动容器（顺序：agent → backend → frontend）

### 2.1 AI 服务（FastAPI）

```bash
docker run -d --name witpath-agent \
  --network witpath \
  -p 8000:8000 \
  -v /opt/witpath/agent/.env:/app/.env:ro \
  -e PG_DSN=postgresql://admin:admin123@postgresql:5432/witpath_ai \
  -e MILVUS_HOST=milvus \
  --restart unless-stopped \
  witpath-agent:latest
```

- `.env` **不打进镜像**：把开发机的 `Agent/.env`（含 ARK/DashScope 密钥）
  拷到服务器 `/opt/witpath/agent/.env` 后只读挂载，pydantic 启动时自动加载；
- `-e` 覆盖 `.env` 里指向 127.0.0.1 的中间件地址（服务器无 ollama 容器，
  embedding 走 dashscope 在线服务，无需覆盖 OLLAMA_HOST）。

### 2.2 后端（Spring Boot）

```bash
docker run -d --name witpath-backend \
  --network witpath \
  -p 8080:8080 \
  -e WITPATH_DB_HOST=mysql \
  -e WITPATH_REDIS_HOST=redis \
  -e WITPATH_MQ_HOST=rabbitmq \
  -e WITPATH_AI_BASE_URL=http://witpath-agent:8000 \
  -v /opt/witpath/backend/storage:/app/storage \
  -v /opt/witpath/backend/log:/app/log \
  --restart unless-stopped \
  witpath-backend:latest \
  --witpath.ai.callback-base-url=http://witpath-backend:8080
```

> 注意 `--restart unless-stopped` 必须放在镜像名**之前**；镜像名之后的
> `--witpath.ai.callback-base-url=...` 是 Spring 程序参数，用于把「AI 进度回调
> 地址」从默认 127.0.0.1 指向后端容器自身（该配置不在 yaml 占位符体系里，
> 用程序参数最稳妥）。

- 端口/账号全部沿用默认值（3306/6379/5672、root/123456、admin/admin123），只改主机名；
- `/app/storage` 本地资料与 `/app/log` 业务日志（含 userlog.txt）挂宿主机目录持久化。

### 2.3 前端（Nginx）

```bash
docker run -d --name witpath-frontend \
  --network witpath \
  -p 80:80 \
  --restart unless-stopped \
  witpath-frontend:latest
```

Nginx 反代规则与开发态 Vite 代理一致：`/api`、`/login`、`/register`、
`/public`、`/files` 原样透传给 `witpath-backend:8080`，其余走 SPA 路由；
浏览器直达 `/login`、`/register` 页面时不会被误转发到后端。

## 3. 验证

```bash
docker ps                                        # 三个应用容器 Up（agent 显示 healthy）
docker logs -f witpath-backend                   # 看到 Spring 启动完成
curl http://127.0.0.1/public/health              # 后端健康检查（经宿主机端口）
curl http://127.0.0.1/                           # 前端页面（返回 index.html）
docker exec witpath-agent python -c \
  "import urllib.request;print(urllib.request.urlopen('http://witpath-backend:8080/public/health').status)"
                                                 # agent → backend 容器网络连通
```

注册一个用户后，宿主机 `/opt/witpath/backend/log/userlog.txt` 应出现
带归属地与 source 字段的记录。

## 4. 更新部署

```bash
docker build -t witpath-backend:latest backend/WitPath
docker rm -f witpath-backend && <重跑 2.2 的 docker run 命令>
```

（也可把三个 `docker run` 存成脚本 `deploy.sh`，更新时先 build 再 rm + run。）
