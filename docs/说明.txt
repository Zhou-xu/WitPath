# 学途知行 AI 协作平台（WitPath）

## 一、项目简介

学途知行 AI 协作平台（WitPath）是一款面向学生群体的智能学习管理与辅助决策平台，旨在帮助学生记录日常学习过程、跟踪学习进度、制定学习目标，并通过人工智能技术对学习情况进行综合分析，为学生提供个性化的学习建议、进度提醒与目标调整指导。

平台围绕学生的学习全过程构建数字化学习管理体系，将学习记录、目标规划、进度追踪、学习资料管理与 AI 智能分析相结合，形成从学习计划制定、学习过程记录到学习效果分析和后续规划优化的完整闭环。

项目采用前后端分离架构，以 Vue 3 构建用户交互界面，以 Spring Boot 作为核心业务后端，通过 RabbitMQ 实现异步消息处理与业务解耦，并使用 FastAPI 构建独立的 AI 服务层。AI 模块结合 LangChain 与 LangGraph 实现多 Agent 协作、任务编排及智能分析，同时利用 MySQL、Redis、PostgreSQL、Milvus 和阿里云对象存储等技术支撑业务数据管理、缓存、知识检索与学习资料存储。

平台致力于打造一个集 **学习管理、目标规划、智能分析、知识检索与个性化学习建议** 于一体的 AI 学习协作平台。

## 二、项目建设目标

1. **学习过程数字化：** 记录学生日常学习行为、学习内容、学习时长及阶段性成果，形成持续积累的个人学习档案。
2. **学习目标可视化：** 支持学习目标制定、任务拆解、计划安排与完成进度跟踪，帮助学生明确学习方向。
3. **学习进度智能化：** 根据学习记录与目标完成情况分析学习进展，识别计划偏差及潜在风险。
4. **学习建议个性化：** 利用 AI 对学生的学习数据和学习资料进行综合分析，生成针对性的学习建议和规划优化方案。
5. **系统架构模块化：** 通过前后端分离、消息队列和独立 AI 服务，降低模块间耦合，提高系统的可维护性与扩展能力。
6. **学习知识可检索化：** 结合向量数据库与知识检索技术，为学习资料查询、上下文检索和 AI 辅助分析提供支持。

## 三、核心功能模块

### 3.1 学习记录管理

用于记录学生日常学习活动，形成持续积累的学习数据。

- 学习记录的创建、查看、修改与管理。
- 学习内容、学习时长及学习成果记录。
- 按日期、学习任务或学习目标查看历史记录。
- 汇总学习数据，为后续进度统计和 AI 分析提供依据。

### 3.2 学习目标与计划管理

帮助学生制定阶段性学习目标，并将目标转化为可执行的学习任务。

- 创建和维护个人学习目标。
- 设置目标周期、计划内容与完成标准。
- 将较大的学习目标拆解为阶段性任务。
- 跟踪任务完成状态和整体目标进度。
- 根据实际学习情况调整后续学习安排。

### 3.3 学习进度分析

基于学习记录、目标计划和任务完成情况，对学习过程进行统计与分析。

- 统计学习时长、任务完成数量及目标完成率。
- 对比计划进度与实际进度。
- 识别学习任务延期、学习投入不足等潜在问题。
- 为学习趋势分析和计划调整提供数据支持。

### 3.4 AI 智能学习助手

通过独立 AI 服务整合大语言模型、Agent 协作及知识检索能力。

- 分析学生的学习记录与目标完成情况。
- 根据用户需求生成学习规划建议。
- 对学习进度偏差进行分析并提供调整方案。
- 结合学习资料回答相关问题。
- 根据分析结果生成学习提醒与改进建议。

具体分析能力、提醒策略及 Agent 分工可根据项目实际实现逐步扩展。

### 3.5 学习资料管理

用于统一管理学生上传的学习资料，为资料查阅和 AI 知识检索提供基础。

- 学习资料上传、存储与管理。
- 保存资料的基本信息及关联关系。
- 通过阿里云 OSS 存储文件内容。
- 对适用的文档进行解析、文本切分与向量化处理。
- 将处理后的知识内容接入向量检索与 AI 问答流程。

### 3.6 智能提醒与建议

结合学习目标、计划进度和 AI 分析结果，为学生提供及时的学习辅助。

- 学习任务及目标时间提醒。
- 任务延期和进度偏差提示。
- 阶段性学习情况总结。
- 个性化学习策略与目标调整建议。

提醒的触发条件、推送方式及执行周期由具体业务实现决定。

## 四、系统技术架构

项目采用前后端分离与 AI 服务独立部署的总体架构，各技术组件按照职责划分，协同完成学习业务处理与智能分析。

### 4.1 技术选型

| 技术层级 | 技术组件 | 主要职责 |
|---|---|---|
| 前端展示层 | Vue 3 | 构建用户界面与交互功能 |
| 前端构建工具 | Vite | 前端开发、构建与资源管理 |
| 后端业务层 | Spring Boot | 处理核心业务、用户请求及业务规则 |
| 异步消息层 | RabbitMQ | 消息传递、异步任务调度与模块解耦 |
| AI 服务层 | FastAPI | 提供 AI 能力的 HTTP API 接口 |
| Agent 编排 | LangGraph | 管理多 Agent 工作流、状态及执行流程 |
| 大模型应用框架 | LangChain | 整合模型调用、提示词、工具及检索组件 |
| 关系型业务数据库 | MySQL | 持久化核心业务数据 |
| 缓存与辅助存储 | Redis | 缓存热点数据、支持过期数据管理及适用的任务协调场景 |
| AI 业务数据存储 | PostgreSQL | 存储 AI 模块所需的结构化数据及按需配置的工作流状态 |
| 向量数据库 | Milvus | 存储向量并执行语义相似度检索 |
| 对象存储 | 阿里云 OSS | 存储学习文档及其他非结构化文件 |

说明：PostgreSQL 的具体职责应以项目实际实现为准，例如可用于 LangGraph 工作流持久化或 AI 模块的结构化数据存储；LangChain 与 LangGraph 的具体组件和数据库集成方式也取决于实际配置。

### 4.2 系统架构说明

系统按照职责划分为四个主要层次：

**第一层：前端交互层**

基于 Vue 3 构建学习管理界面，负责接收用户操作、展示学习记录、目标计划、进度统计和 AI 分析结果，并通过 HTTP API 与后端服务通信。

**第二层：核心业务服务层**

基于 Spring Boot 构建，负责用户请求处理、学习业务规则执行、业务数据读写、权限控制以及异步任务的发起与结果管理。

**第三层：异步消息处理层**

基于 RabbitMQ 实现业务消息的生产、传递和消费。对于学习分析、文档处理等适合异步执行的任务，可通过消息机制降低请求等待时间，减少业务模块间的直接依赖。

**第四层：AI 智能服务层**

基于 FastAPI 对外提供 AI 服务接口，利用 LangChain 集成大模型与检索能力，通过 LangGraph 组织多 Agent 协作流程，并结合 PostgreSQL、Milvus 和阿里云 OSS 完成状态管理、知识检索与资料访问。

各层通过明确的接口进行协作，使业务服务和 AI 服务可以独立开发、调试与扩展。

## 五、AI 多 Agent 协作机制

### 5.1 技术设计

AI 模块采用 FastAPI + LangChain + LangGraph 的技术组合，构建独立于核心业务后端的智能分析服务。

- **FastAPI：** 提供 AI 服务 API，负责请求接收、参数校验及结果返回。
- **LangChain：** 负责大模型调用、提示词组织、工具集成和知识检索等任务。
- **LangGraph：** 负责组织 Agent 执行节点、管理工作流状态、控制节点间流转，并支持按需配置条件分支与失败处理。
- **PostgreSQL：** 可用于持久化 AI 工作流状态、执行记录或其他结构化数据。
- **Milvus：** 为学习资料提供向量检索能力，帮助 AI 获取与当前问题相关的知识片段。
- **阿里云 OSS：** 保存原始学习资料，供资料解析和检索处理流程使用。

### 5.2 多 Agent 任务分工

可根据业务需求将 AI 工作流划分为以下逻辑角色：

1. **学习数据分析 Agent：** 整理学习记录、目标完成情况和相关统计信息。
2. **学习规划 Agent：** 根据目标、剩余时间和当前进度，生成或调整学习计划。
3. **知识检索 Agent：** 根据用户问题检索相关学习资料，并组织可供模型参考的内容。
4. **学习建议 Agent：** 综合分析结果，生成学习策略、改进建议和风险提示。
5. **结果整合节点：** 汇总各分析环节的结果，生成结构化的最终答复。

以上为建议的逻辑职责划分，并不意味着项目当前已经实现五个独立 Agent。实际 Agent 数量、工具调用方式与工作流拓扑应以代码实现为准。

### 5.3 AI 分析流程

一次典型的学习分析任务可按以下流程组织：

1. 接收用户提出的学习分析需求。
2. 通过业务后端或授权接口获取所需的学习数据。
3. 对学习记录、目标和进度进行整理。
4. 根据任务需要调用知识检索或相关工具。
5. 由 LangGraph 按预设工作流调度相应 Agent。
6. 整合各分析环节的结果并生成学习建议。
7. 将结果返回业务后端，并根据业务需要保存分析记录。
8. 前端展示分析结果，并在满足提醒条件时执行后续提醒逻辑。

对于需要较长时间处理的任务，可以采用 RabbitMQ 进行异步调度，避免用户请求长期占用同步处理链路。

## 六、数据库与存储设计

### 6.1 MySQL：核心业务数据库

MySQL 作为平台的主要关系型数据库，负责保存学习业务所需的结构化数据，例如：

- 用户与账号相关信息。
- 学习记录及学习活动数据。
- 学习目标、任务与计划信息。
- 学习进度统计所需的业务数据。
- 学习资料元数据及关联信息。
- AI 分析结果与提醒记录等业务数据。

具体表名、字段、主外键关系、索引与约束以项目 `database` 目录中的 SQL 脚本及数据库设计文件为准。

### 6.2 Redis：缓存与辅助数据管理

Redis 主要用于提升高频数据访问效率，适用于：

- 热点业务数据缓存。
- 登录状态或临时数据管理，具体取决于认证方案。
- 有过期时间要求的临时数据。
- 在适用场景下实现任务协调或轻量级计数。

Redis 中的数据应根据业务重要性设计过期策略、缓存更新方式及必要的持久化策略，不应在未经设计的情况下将缓存作为核心业务数据的唯一存储。

### 6.3 PostgreSQL：AI 模块的数据支撑

PostgreSQL 供 AI 模块使用，可根据实际架构承担以下职责：

- AI 分析任务及执行记录的结构化存储。
- LangGraph 工作流状态持久化。
- 需要事务保障的 AI 辅助业务数据存储。
- 与向量检索相关的辅助元数据管理。

实际存储范围应以代码与配置为准，避免与 MySQL 重复保存同一业务实体而缺乏明确的数据同步规则。

### 6.4 Milvus：向量检索

Milvus 专门用于存储和检索向量数据，可支持学习资料的语义搜索与知识检索。

典型处理流程：

1. 获取 OSS 中的学习资料。
2. 对支持的文件格式进行文本解析。
3. 将文本切分成适当大小的片段。
4. 调用 Embedding 模型生成向量。
5. 将向量、文本标识及必要元数据写入 Milvus。
6. 用户提问时，将问题转换为向量并检索相关片段。
7. 将检索结果交给 AI 模型生成有上下文依据的回答。

Milvus 中的向量维度、索引类型、距离度量、Collection 结构与元数据字段应根据实际使用的 Embedding 模型和检索需求进行设计。

### 6.5 阿里云 OSS：学习资料存储

阿里云对象存储服务 OSS 用于保存学习资料等非结构化文件，例如文档、图片及其他支持的附件。

建议将文件实体与业务元数据分开管理：

- OSS 保存实际文件对象。
- MySQL 保存文件名称、所属用户、文件类型、对象标识及业务关联信息。
- AI 文档处理流程读取文件内容，完成解析、切分和向量化。
- Milvus 保存检索所需的向量及关联标识。

访问 OSS 时应妥善管理访问凭证、存储桶权限和文件访问策略，避免公开暴露私有学习资料。

### 6.6 数据库设计文件说明

项目数据库表结构及初始化 SQL 存放在项目的 `database` 目录中。

该目录作为数据库结构设计、初始化脚本和相关数据库文档的集中管理位置，便于开发人员了解各业务实体、字段定义、数据关系及初始化流程。

数据库相关说明应与实际 SQL 脚本保持一致，确保表名、字段类型、约束条件及索引设计能够准确反映当前项目实现。

## 七、RabbitMQ 异步业务处理机制

RabbitMQ 用于连接核心业务服务与适合异步处理的任务执行流程，实现业务模块解耦。

典型应用场景包括：

- 学习资料解析与向量化任务。
- AI 学习分析任务。
- 学习报告生成任务。
- 非实时提醒或通知任务。

### 7.1 典型任务流程

1. 前端提交学习分析或资料处理请求。
2. Spring Boot 校验请求并创建相应业务任务记录。
3. 后端将任务消息发送至 RabbitMQ。
4. 消费者接收消息，并调用 AI 服务或相应的处理模块。
5. 处理模块完成任务并记录执行结果。
6. 后端更新任务状态，前端根据查询接口或适用的消息推送机制获取处理进度和结果。

### 7.2 设计原则

- **异步解耦：** 将耗时任务从同步业务请求中分离。
- **可靠投递：** 根据任务重要性配置消息确认、持久化及必要的重试机制。
- **幂等处理：** 防止消息重复消费造成重复执行或重复写入。
- **失败恢复：** 设计异常记录、有限重试和死信处理策略。
- **状态可追踪：** 记录任务标识、执行状态、失败原因及必要的时间信息。

RabbitMQ 负责消息传递，并不意味着它自动保证业务任务只执行一次。业务层仍需处理重复消息、消费失败和结果一致性等问题。

## 八、核心业务流程

### 8.1 学习记录与进度跟踪

学生创建学习记录 → 后端校验并保存数据 → 更新相关统计信息 → 前端展示学习历史和进度 → 为后续学习分析提供数据。

### 8.2 学习目标规划

学生创建学习目标 → 设置目标周期与任务 → 后端保存目标计划 → 根据学习记录持续更新进度 → 分析计划与实际完成情况 → 提供必要的调整建议。

### 8.3 AI 智能学习分析

学生发起分析请求 → 后端校验权限并准备数据 → 根据任务类型调用 AI 服务或异步消息处理 → LangGraph 调度相应分析流程 → Agent 结合业务数据和知识检索完成分析 → 保存结果并返回前端 → 根据规则提供提醒或建议。

### 8.4 学习资料知识检索

学生上传资料 → 文件存储至 OSS → 后端保存资料元数据 → 文档处理任务执行解析与切分 → Embedding 模型生成向量 → 向量数据写入 Milvus → 用户提出相关问题 → 检索相关资料片段 → AI 根据检索内容组织回答。

## 十、系统安全与可靠性设计

1. **身份认证与权限控制：** 根据业务需求实现用户身份认证、接口访问控制及数据访问权限校验。
2. **敏感信息保护：** 对数据库密码、模型 API Key、OSS 凭证等敏感配置采用环境变量或安全配置管理方式。
3. **文件访问安全：** 对上传文件进行必要的类型、大小与权限校验，避免未授权访问。
4. **AI 数据访问控制：** 仅向 AI 分析流程提供当前用户有权访问的数据，并对学习资料检索结果进行权限约束。
5. **消息处理可靠性：** 对异步任务配置必要的确认、重试、幂等及失败记录机制。
6. **运行日志与问题排查：** 记录必要的请求、任务及异常信息，避免在日志中暴露密码、Token 和敏感学习内容。
7. **服务边界管理：** 对 Spring Boot、FastAPI、RabbitMQ 和数据库等服务配置合理的访问范围及认证机制。

## 十一、部署与运行说明

项目部署前，需要根据实际代码和运行环境完成以下准备工作：

1. 安装与项目兼容版本的 JDK、Node.js、Python 和相关包管理工具。
2. 部署 MySQL、Redis、RabbitMQ、PostgreSQL 与 Milvus。
3. 配置阿里云 OSS 相关凭证、存储桶和访问权限。
4. 配置 Spring Boot 的数据库连接、消息队列和 AI 服务地址。
5. 配置 FastAPI 的模型服务、Embedding 服务及数据库连接。
6. 根据项目实际依赖安装前端与 AI 服务所需的依赖包。
7. 按照 `database` 目录中的初始化脚本创建业务表。
8. 依次启动基础设施、后端业务服务、AI 服务和前端应用，并验证服务间通信。

各组件的版本、端口、启动命令和环境变量应以项目配置文件及部署环境为准。

## 十二、项目总结

学途知行 AI 协作平台以学生学习过程管理为基础，以 AI 智能分析为特色，构建集学习记录、目标规划、进度跟踪、资料管理与个性化建议于一体的智能学习辅助系统。

项目通过 Vue 3 与 Spring Boot 实现前后端分离，利用 RabbitMQ 提升异步业务处理能力，通过 FastAPI、LangChain 和 LangGraph 构建独立的 AI 服务与多 Agent 协作流程，并结合 MySQL、Redis、PostgreSQL、Milvus 和阿里云 OSS 分别承担业务数据管理、缓存、AI 数据持久化、向量检索及文件存储等职责。

通过上述技术架构，平台能够为后续扩展智能学习规划、知识库问答、阶段性学习报告与个性化提醒等功能提供基础，并逐步形成从学习数据积累到智能反馈与规划优化的完整学习闭环。
